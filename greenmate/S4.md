# B07 第一遍 S4：多源证据分歧

固定问题与 B06 `attention_v1` 不变，不接 S5。`llm.py`、`agent.py` 和模型文件保持 S3 的字节摘要；解释层在 `evidence.py` 追加证据约束，复用现有模型配置和重试传输。

## 运行

```json
POST /api/analyze/scenario
{"name":"S4_conflict","include_weather":true,"include_knowledge":true}
```

也可直接向 `/api/analyze` 传 `include_knowledge`（严格布尔值，默认 false），使用当前状态与已有历史。两种路径都不允许传入替代固定问题。页面提供“S4 · 含知识”和“关闭知识”两个按钮，并可按 run_id 恢复卡片、追踪、冲突和解释。

S4 内部仅写入标注为 `SIMULATED / S4_conflict` 的六点：27→32°C、18000→24000 lux、65%空气湿度。只替换受管场景，不覆盖真实或非场景样本，不修改既有分析快照。模型输出 NORMAL 或 WATCH 均原样保存。天气由原有 B05 工具实时获取，某次天气不降温时不伪造方向冲突。

天气工具只新增 `User-Agent: GreenMate/1.0` 请求头：本环境中默认Python标识超时，明确产品标识可正常取得预报。接口、参数、5秒超时、校验和返回契约不变。保留原S3摘要文件；回归测试去掉这一个请求头后核对原工具文件完整摘要，避免掩盖其他变更。

## 字段与采纳

- `judgment.evidence_by_type`：五类候选证据均具备 `source_type/source/time/status/result/error`。天气保留 provider、retrieved_at、forecast_time；知识保留 citation；模型保留 model_version。
- `judgment.evidence_records`：保留通过校验且被采用的证据，以及未启用知识/天气时的 unavailable 记录（time=analysis_time、result=null，error说明关闭原因）。仅采用 status=ok 的记录参与判断；关闭的工具不进入 tool_trace。空命中、其他植物、无效引用、身份时间缺失、过期预报仍不作为已采用证据。
- `judgment.knowledge`：知识候选状态；关闭时为 unavailable，结果为空。`evidence_status.knowledge` 与旧字段 plant_knowledge 并存。
- `tool_trace`：归档在 analysis_runs 新增的 tool_trace_json 列。每项包括 tool、原始工具status、adopted、adopt_reason、实际arguments、对应source_type。未调用的工具不伪造一项；SQL历史读取与锚定模型推理不是 B05 工具调用。
- `judgment.conflicts`：仅依采用证据产生，包括 HISTORY 与 WEATHER_FORECAST 的方向分歧；NORMAL 与高温知识条件之间的关注差异使用 attention_divergence，不说任一方被证伪。
- `conclusion_level`：有未消解分歧则 conflicting；无分歧但核心当前/历史/模型不全则 insufficient；其余 supported 仅支持各自范围内的描述，不保证未来状态。

`status=ok` 只是工具成功返回，**不等于采纳**。例如知识工具可以成功返回空数组；天气工具也可以返回数值，但预报全部早于锚点。此时追踪仍为 status=ok，adopted=false；前者保留“无有效引用”，后者保留“时间不适用”的理由。

历史是内部过去过程，天气是户外未来预报，模型是基于合成规则标签的下一小时注意力输出，知识是条件性背景。空间、时间和推断目标均不同。`conflicting` 保留每条依据与缺口，比把它们平均成确定恶化更可核查；当前缺少内部后续实测、内外温度耦合、品种/生育期与土壤水分。

## 知识引用

`knowledge/plants.json` 每条维护稳定 id。检索结果附 `citation: {id, name, snippet}`；snippet 从条目原文提取。B05 注册的 search_plant_knowledge 在分析链内实际执行，分析模块不导入 rag。query 包含当前状态和原固定问题。

原向量模型与相似度门槛不改。知识索引输入新增温湿度/高温字段；显式植物实体命中优先约束返回物种（对所有条目通用，不专门硬编码番茄），其他查询保留向量检索与关键词回退。维护文件必须显式有 id；兼容旧外部 fixture 的无 id 条目仅用名称哈希提供稳定引用。

番茄条目包括温室白天约24–27°C、昼夜条件下的夜温参考、温室空气相对湿度约60–70%、至少6小时日照说明，以及约29.4°C的条件性高温管理参考。瞬时lux不换算为日照时长，也不据此诊断伤害。依据：

- [UMass / New England Vegetable Management Guide](https://nevegetable.org/crops/tomato-greenhouse-and-high-tunnel)
- [University of Maryland Extension](https://www.extension.umd.edu/resource/growing-tomatoes-home-garden)
- [Mississippi State University Greenhouse Tomato Handbook](https://extension.msstate.edu/sites/default/files/publications/publications/p1828_web.pdf)

## 输出保护与验证

解释须引用采纳的知识id，保留 conflicting 与分歧、缺口。程序检查确定性词、遗漏分歧和未采纳知识却声称引用知识的文本；不合格时最多重新生成一次，仍失败则 answer 为空并归档 EXPLANATION_REJECTED，不伪造LLM回答。

```sh
.venv/bin/python -m unittest discover -q
.venv/bin/python verification/s4_live.py
```

`verification/s4_live.json` 区分真实网络与本地推理，各检查按实际结果保存。`s4_ui_server.py` / `s4_ui.cjs` 使用显式标注的天气和解释测试数据，只证明界面交互，不证明真实天气成功。真实预报不可用时保留 unavailable，不以UI测试数据替代联网验收。独立验收数据库不覆盖原greenmate.db。
